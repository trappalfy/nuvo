# Nuvo: протокол двойных инвестиций на Robinhood Chain

Дата: 2026-09-23. Статус: согласован, готов к плану реализации.

Сайт готов и работает вхолостую. Эта спецификация описывает то, чего ему не
хватает: контракты, которые принимают деньги, платят премию и рассчитываются
по пятничной цене Chainlink. Сервера в системе нет.

## 1. Решения, принятые при обсуждении

| Решение | Выбор |
| --- | --- |
| Кто берёт другую сторону | Пул вкладчиков: любой вносит средства и зарабатывает на премиях |
| Откуда премия | Формула в контракте; сервиса котировок и подписей нет |
| Чем обеспечены выплаты | Только запасом пула; докупок на бирже нет |
| Устройство пула | Изолированный пул на каждый тикер, два актива внутри |
| Страйк | Фиксируется в момент подписки от текущей цены |
| Обновляемость | Пулы неизменяемы; новая версия = новый пул |

## 2. Проверенные факты о сети

Прочитано напрямую из мейннета 2026-09-23, а не из документации.

| Что | Значение |
| --- | --- |
| Сеть | Robinhood Chain mainnet, chain id `4663`, газ ETH |
| RPC | `https://rpc.mainnet.chain.robinhood.com` (публичный, с лимитами; для продакшена платный провайдер) |
| Обозреватель | `https://robinhoodchain.blockscout.com` |
| Тестнет | chain id `46630` |
| USDG | `0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168`, 6 десятичных |
| Токены акций | ERC-20, 18 десятичных, `uiMultiplier()` в формате 1e18 (сейчас 1.0) |
| Фиды | 35 фидов на акции и ETF, 8 десятичных, отклонение 0.5%, режим 24/5 |
| Справочник фидов | `https://reference-data-directory.vercel.app/feeds-robinhood-mainnet.json` |

Ключевое: **фид отдаёт цену за токен с уже учтённым множителем**, а не за
акцию. Все расчёты в контракте и в интерфейсе ведутся в токенах.

Минт и сжигание токенов доступны только авторизованным участникам. Протокол
лишь перемещает существующие токены, поэтому это ограничение нам не мешает.

## 3. Контракты

`NuvoPoolFactory` — деплоит пулы, ведёт реестр «токен → пул», хранит адреса
фидов и общие параметры расписания. Пул, созданный не фабрикой, протоколом не
считается.

`NuvoPool` — один на тикер. Хранит USDG и токен акции. Три раздельных учёта:

1. **инвентарь вкладчиков** — из него платятся премии и выдаются конверсии;
2. **обязательства перед подписчиками** — их депозиты и причитающиеся выплаты;
3. **паи вкладчиков** — доля в инвентаре.

`PremiumModel` — формула премии, отдельный контракт. Возвращает ставку в bps по
(направление, расстояние до цели). Пул отвергает ставку выше своего потолка.

Роли: `owner` (мультиподпись) — лимиты, модель премий, пауза; `guardian` —
только аварийная остановка подписок. Ни одна роль не может тронуть депозиты
подписчиков или вывести инвентарь вкладчиков.

Расчёт (`settle`) открыт для всех. Наш бот — подстраховка, а не условие работы.

## 4. Модель данных

```
Position {
  owner, direction, deposit, strike, premiumBps,
  expiry, settled, claimed, payoutAsset, payoutAmount
}
```

Страйк и премия фиксируются в позиции при подписке. Расчётная цена хранится
одна на (тикер, экспирация) — позиции сравнивают свой страйк с ней.

Единицы: USDG 6 знаков, токен 18, цена 8. Внутренние вычисления в 1e18,
округление всегда в пользу пула, остаток не более 1 wei.

## 5. Жизненный цикл

**Календарь экспираций.** «Пятница 16:00 ET» смещается в UTC дважды в год из-за
перехода на летнее время, поэтому контракт не вычисляет её сам. Фабрика хранит
календарь: список отметок времени экспираций, публикуемый заранее на месяцы
вперёд. Любой может сверить их с расписанием биржи. Подписка привязывается к
ближайшей экспирации, до которой осталось больше суток: до четверга 16:00 ET это
ближайшая пятница, после — следующая. Так на цепочке повторяется круглосуточный
приём подписок, который уже работает на сайте.

**Подписка.** Пользователь передаёт депозит, выбирает направление и расстояние
до цели. Контракт читает цену, проверяет её свежесть, считает страйк и премию,
замораживает инвентарь под оба исхода и создаёт позицию.

Buy Low, депозит `D` USDG, страйк `K`, премия `r`:
- замок под конверсию: `D × (1 + r) / K` токенов;
- замок под отказ: `D × r` USDG.

Sell High, депозит `Q` токенов:
- замок под конверсию: `Q × K × (1 + r)` USDG;
- замок под отказ: `Q × r` токенов.

Если свободного инвентаря не хватает на оба замка — подписка отклоняется.

**Расчёт.** После экспирации любой вызывает `settle(expiry)`. Контракт берёт
цену из фида, проверяет свежесть и записывает её как расчётную. Если свежей
цены нет (праздник, сбой) — расчёт ждёт первой свежей.

**Выплата.** `claim(positionId)`: Buy Low при цене на страйке или ниже даёт
`D × (1 + r) / K` токенов, иначе `D × (1 + r)` USDG. Sell High при цене на
страйке или выше даёт `Q × K × (1 + r)` USDG, иначе `Q × (1 + r)` токенов.
Неиспользованный замок возвращается в инвентарь. Срока давности нет.

**Как сайт узнаёт цифры.** Вместо сервиса котировок у пула есть функция
просмотра: по направлению, расстоянию до цели и сумме она возвращает премию,
страйк, оба исхода и признак того, хватает ли инвентаря. Один вызов — всё, что
нужно экрану подписки.

**Комиссия протокола** — доля от премии, на старте 0, удерживается при расчёте
из инвентарной части. Депозит подписчика комиссией не облагается.

## 6. Паи вкладчиков

Стоимость пула = свободный и замороженный USDG плюс свободные и замороженные
токены по цене фида. Депозиты подписчиков и их будущие выплаты в неё не входят.

Ввод: вкладчик вносит USDG или токен, получает паи по текущей стоимости пула.
Первый вклад задаёт масштаб. Вывод: сжигает паи и получает долю **из свободной
части** обоих активов. Замороженное недоступно до расчёта — это честная цена
за гарантию выплат.

Ввод и вывод запрещены при несвежей цене: иначе стоимость пая можно занизить.

## 7. Риск и аварийные режимы

- потолок замороженного на неделю: на пул и на одну позицию;
- минимальная сумма подписки;
- потолок доли инвентаря в работе, чтобы вкладчики могли выйти;
- допустимый возраст цены: раздельно для часов работы биржи и остального времени;
- потолок премии зашит в пул; смена модели премий — с задержкой;
- пауза останавливает только подписки и вклады. Расчёт и выплата не
  останавливаются никогда, иначе пауза запирает чужие деньги;
- пул создаётся только под канонический токен из реестра Robinhood с живым фидом.

## 8. Инварианты

1. Сумма обязательств перед подписчиками ≤ фактический баланс контракта.
2. Свободный инвентарь ≥ 0 в любой момент.
3. Депозит подписчика не может быть израсходован на выплату другому.
4. Сумма замков позиции покрывает любой её исход.
5. Паи не создаются и не сжигаются иначе как при вводе и выводе вкладчика.

## 9. Тесты (только то, что стережёт деньги)

- четыре исхода: Buy Low с конверсией и без, Sell High с конверсией и без;
- инварианты из раздела 8 под случайными последовательностями действий;
- отказы: не хватает инвентаря, превышен лимит, несвежая цена, чужой claim;
- один прогон на форке мейннета с настоящими USDG, токеном и фидом.

Пропускаем: оптимизацию газа, отчёты о покрытии, e2e фронтенда, скриншоты.

## 10. Порядок запуска

1. Тестнет 46630: полный цикл, включая пятничный расчёт.
2. Мейннет с жёстким потолком объёма, в пуле только наши деньги.
3. Снятие потолка после нескольких отработанных недель.
4. Приём чужих средств — после внешнего аудита. Решение за владельцем.

## 11. Правки на сайте

- убрать сервис котировок: премия читается из контракта (`QUOTE_API` уходит);
- считать в токенах: снять двойное умножение на `uiMultiplier`;
- раздел вкладчика пула: внести, вывести, доля, доходность;
- предупреждение, что для комиссии сети нужен ETH;
- `.env`: адреса фабрики и реестр пулов вместо адреса одного контракта.

## 12. Вне рамок этого этапа

Досрочный выход из позиции, вторичный рынок позиций, кросс-чейн, собственный
токен протокола, управление через голосование, автоматическое хеджирование.
